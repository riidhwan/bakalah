# Auto-Tag Merged Release Branches

Bakalah release intent is a reviewed pull request from a same-repository `release/MAJOR.MINOR.PATCH` branch merged into `main`, not a maintainer pushing a release tag by hand. The merged pull request identifies one immutable revision and remains the authoritative intent before any tag exists. Only one merged-but-unpublished intent may exist; an unshippable intent can be superseded only by a later reviewed Release Branch pull request that identifies and explains the replacement.

The merged-pull-request workflow independently validates the exact merged revision, builds and verifies its complete artifact set, then creates an annotated `vMAJOR.MINOR.PATCH` tag as a publication result. A manually pushed tag cannot initiate publication. The final publication job alone receives `contents: write` and uses the ephemeral `GITHUB_TOKEN`; build jobs remain read-only and receive signing credentials without repository write access. This removes the separate tag-push event chain and its GitHub App credential while preserving immutable annotated tags.
