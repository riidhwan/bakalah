# Permanently Delete Vault Manga

Bakalah will define manga-level Vault Deletion as permanent removal from the authoritative Vault Collection rather than a recoverable move to Vault Trash. The root manifest pointer removal is the authoritative deletion; after that publish succeeds, Bakalah deletes the remote manga manifest, chapter CBZ files, and cover assets as cleanup, treats missing remote files as already clean, reports other cleanup failures without rollback, and removes app-managed local index, reading state, cache, transfer jobs, manifest snapshots, and import target hints for the deleted Vault Manga. Cleanup failures are one-shot warnings/logs rather than durable retryable transfer jobs; orphan cleanup belongs to future diagnostics or repair tooling. The Vault Layout Version will be bumped when trash fields are removed from manifests, so older Bakalah builds refuse to edit hard-delete vaults instead of assuming trash-capable semantics; existing layout-v1 vaults remain readable, but the first publish operation upgrades written manifests to layout v2 and drops any v1 trashed entries from the authoritative catalogue. This replaces the trash-based deletion model from ADR 0004 because no restore or empty-trash workflow exists, and keeping unreachable vault content would make a user-requested deletion misleading while continuing to consume remote storage.
